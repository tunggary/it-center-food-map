# 참여형 최애 지도 서비스 요구사항

사용자와 검토한 기능적·비기능적 요구사항이다. 초기의 추천·좋아요·댓글과 숨김·복구 기능은 최종 결정에 따라 제외했다. 기술 선택·구현은 이번 단계에서 다루지 않는다.

## 1. 목적과 운영 방향

- 완성차 IT 센터 CA 활동에서 동료들의 최애 장소·산책코스를 함께 지도에 모은다.
- 핵심 성공 기준은 **즐거운 현장 참여 경험**이며, 현장 피드백으로 확인한다.
- 삼성역 인근을 기본 탐색 지역으로 하되 다른 지역의 등록도 허용한다.
- 행사 이후에도 계속 참여할 수 있다.
- 첫 배포 이후 별도 v2 없이 사용자 피드백에 따라 개선한다. 의견은 부스 운영자가 직접 받는다.

## 2. 접속과 참여자 정보

- QR 또는 웹 주소로 접속하며, 주소를 아는 누구나 이용할 수 있다.
- 로그인 없이 지도·랭킹을 바로 열람한다.
- 첫 최애 등록 시 문구·사진을 작성하는 과정에서 닉네임과 사전 등록된 팀을 함께 입력한다. ‘기타’ 팀은 제공하지 않는다.
- 닉네임 중복은 허용하며, 수정하면 기존 등록에도 반영한다.
- 팀은 참여자가 변경할 수 없고, 운영자가 정정하면 기존 등록과 집계에 반영한다.
- 동일인 구분은 같은 기기·브라우저 수준으로 한다. 다른 기기나 사용 기록 삭제를 통한 재참여 가능성은 허용한다.

## 3. 최애 등록과 관리

- 새 장소·코스를 등록하거나 기존 항목을 **‘나도 최애로 등록’**할 수 있다.
- 등록마다 문구 **1~100자 필수**, 사진 **최대 3장 선택**이다.
- 등록 완료 후 해당 장소·코스 상세로 이동해 자신의 문구·사진과 증가한 등록 횟수를 확인한다.
- 한 사람은 같은 장소·코스를 카테고리와 관계없이 한 번만 등록한다. 서로 다른 항목의 등록 개수는 제한하지 않는다.
- 닉네임·팀·문구·사진은 누구나 볼 수 있다.
- ‘내 최애’에서 자신의 등록을 모아보고 문구·사진·카테고리를 수정하거나 등록을 삭제한다.
- 별도 추천·좋아요·댓글 기능은 없다.

## 4. 장소·산책코스·카테고리

- 장소는 검색 결과나 지도에 표시된 실제 장소를 선택한다. 임의 위치·장소명으로 직접 등록하지 않는다.
- 산책코스는 **이름과 이동 경로가 필수**다. 거리·예상 시간은 지도 서비스에서 제공 가능하면 표시한다.
- 기존 코스를 선택하면 등록 횟수를 합산한다. 따로 만든 유사 코스는 별개로 취급한다.
- 코스 작성자가 자신의 최애 등록을 삭제해도 다른 사람의 등록이 있으면 코스를 유지한다.
- 공유 코스의 이름·경로 정정은 운영자만 할 수 있다.
- 초기 카테고리는 맛집·카페·산책코스이며, 관리자는 장소형·경로형 카테고리를 추가할 수 있다.
- 같은 장소도 등록자마다 다른 카테고리를 선택할 수 있다.

## 5. 지도와 랭킹

- 순위는 **현재 남아 있는 최애 등록 횟수의 전체 기간 누적**으로 정한다.
- 동점은 공동 순위로 표시한다. 예: 1위·1위·3위.
- 팀과 카테고리를 조합해 조회한다. 팀별 랭킹은 해당 팀 구성원이 등록한 장소·코스의 순위다.
- 지도에는 선택 조건에 해당하는 항목만 표시하고, 횟수에도 같은 조건을 적용한다.
- 상세 화면의 문구·사진도 선택 조건을 먼저 적용하며 전체 보기로 전환할 수 있다.
- 삭제된 등록은 내용과 집계에서 제외한다. 등록이 0건이 된 항목은 공동 지도·랭킹에서도 제외한다.

## 6. 휴대폰과 부스 화면

| 구분 | 요구사항 |
| --- | --- |
| 휴대폰 | 지도 중심, 상단 헤더에 한 줄 장소 랭킹, 누르면 다양한 랭킹 선택, 하단에 등록 버튼 |
| 부스 전용 화면 | 등록 장소 핀, 전체 팀 기준 카테고리별 랭킹, 카테고리별 핀 필터 |
| 부스 알림 | 모든 최애 등록에 대해 닉네임·팀·장소를 상단에 순서대로 표시 |
| 부스 산책코스 | 시작점 핀을 표시하고 선택한 코스의 전체 경로만 노출 |

등록이 몰리면 알림은 순서대로 대기할 수 있지만, 지도·랭킹의 갱신은 알림 대기와 별개로 진행한다.

## 7. 운영자 기능

- 팀·카테고리 추가, 이름 변경, 신규 선택 중단
- 선택 중단된 팀·카테고리의 기존 등록과 조회·랭킹 유지
- 참여자의 팀 오입력 정정
- 공유 코스 이름·경로 정정
- 개별 최애 등록 또는 장소·코스 전체 삭제
- 전체 삭제 전 대상과 함께 삭제될 등록 수 확인
- 숨김·복구 기능은 제공하지 않음

## 8. 사용성·성능·실패 대응

- 참여 환경: 아이폰 Safari·안드로이드 Chrome
- 부스·운영 환경: PC Chrome
- 동시 접속 목표: **100명**
- 정상 네트워크에서 첫 지도·랭킹 표시 **3초**, 사진 없는 등록 완료 **2초** 목표
- 다른 화면의 지도·랭킹에는 등록 결과를 **5초 이내** 반영
- 처음 방문한 사람이 도움 없이 첫 장소 등록을 **2분 이내** 완료하는 것을 목표로 설정. 사진 첨부·코스 작성은 별도
- UI 내 문구는 친근한 말투로 작성한다. 버튼, 안내, 입력 도움말, 완료·오류 메시지에도 일관되게 적용한다.
- 애니메이션은 등록 완료·지도 표시·순위 변화 중심으로 적용하고, 조작을 지연시키지 않으며 ‘동작 줄이기’ 설정 지원
- 그라데이션을 활용한 표현은 제외
- 등록 실패 시 문구·사진을 유지하고 재시도 지원. 반복 제출로 중복 등록되지 않도록 처리
- 연결 끊김 시 마지막 지도·랭킹과 갱신 중단 안내 표시. 재연결 시 최신 상태로 갱신
- 오프라인 등록 완료 기능은 제공하지 않음

## 9. 보류 항목

- **산책코스 작성 방식:** 네이버·카카오 지도의 제공 기능을 확인한 뒤 결정
- **행사 조건:** 행사일·운영 시간·전체 인원·팀 수·현장 네트워크·화면 준비 여부
- **사전 참여 여부:** 행사 전부터 등록을 받을지 미정

행사 조건은 첫 버전 범위와 검증 계획 확정 전에 확인한다. **기술 선택·구현은 이번 단계에서 다루지 않는다.**

## 10. 운영비 제약

2026-10-13 비용 질문에 대한 사용자 답변을 반영한다.

- 월 운영비는 **0원**, 유료 서비스는 사용하지 않는다.
- 기존 유료 계정·서버 없이 새로 구성한다.
- 사용자는 이 서비스를 **개인 프로젝트로 운영**하며, 프론트엔드 배포처는 **Vercel Hobby**로 선택했다. CA 행사에서 함께 사용하는 참여 목적은 유지한다.
- 사용은 행사에 집중되고 이후에는 가끔 참여한다. 행사 종료 후 참여 기능을 닫는다는 뜻은 아니다.
- 무료 서비스의 휴면 후 수동 재개 허용 여부는 아직 확인 중이며, 항상 즉시 사용 가능 요구를 임의로 폐기하지 않는다.
- 기술 구성·무료 한도·실패 대응의 설계 기본안은 [세부 설계](3-architecture/README.md)에 기록한다. 사용량·성능·실제 행사 조건은 구현 후 검증한다.
