## 8. DEC별 구현 기본안


2026-10-13 사용자가 항목별 결정과 나머지 기본안을 채택했다. 아래는 **확정 구현 기준**이다. PRD·스토리·QA 기대 결과에 함께 반영하며, 정책 확정과 제품 테스트 통과는 구분한다.

| DEC | 확정 동작 | 기술 연결·출시 입력 |
| --- | --- | --- |
| DEC-01 | 지도 중심 십자선에 점 추가·마지막 점 취소·완료·이름 입력. 최소 서로 다른 2점, 최대 200점. 관리자는 같은 편집기로 정정. 선 길이는 참고 거리로 표시, 예상 도보 시간은 표시하지 않음 | [ADR-0004](adr/0004-kakao-map-and-courses.md); 직접 경로 작성 채택 |
| DEC-02 | 전체 PRD 범위를 설계. 제품 배포 후 바로 참여, 자동 행사 시작/종료 차단 없음, 행사 후 참여 유지 | 실제 일정·팀 목록·화면/네트워크는 출시 전 운영 입력 |
| DEC-03 | 모바일 기본 전체 팀·전체 카테고리, 최상단 실시간 상위5개 세로 티커(4초·정지 가능). 전체 랭킹은 전체·맛집·카페·산책코스·커스텀 탭. 커스텀 내부 팀/카테고리 필터 기본은 내 팀·전체 카테고리(내 팀 없음/자격 만료는 전체 팀); 탭과 지도 동일 조건. 홈 티커·PC요약·부스 유지. 상세는 필터 없이 전체 등록. 랭킹 20건씩 더 보기, 페이지를 나누어도 순위는 전체 집합에서 계산. 동점 내부 target ID 순. 상세 최신순(created_at,id), 20건씩. 부스 각 카테고리 상위 5건 고정 표시, 동점은 같은 rank 표시·전체 보기 제공. 핀 필터는 랭킹 패널을 제거하지 않음 | 표현 기본값은 변경 비용 낮음; 순위 불변 규칙과 구분 |
| DEC-04 | 문구 trim 후 grapheme 1~100; 닉네임 trim 후 1~20. 사진 형식·크기는 [사진 설계](media.md); 실패 파일은 개별 재시도/제거 가능 | 입력 제한 채택, 서버·클라이언트 검증 일치 |
| DEC-05 | 같은 작성 화면의 실패/재시도는 텍스트·File 유지. 내부 이탈은 확인, 동의하면 폐기. 새로고침·브라우저 종료 복구는 제공하지 않으며 미리 안내. 취소한 프로필은 미생성 | 세션은 유지할 수 있지만 참여자로 집계하지 않음. 초기 오프라인 경계는 [화면 설계](frontend.md) |
| DEC-06 | 낙관적 version 충돌은 내용 유지+다시 확인, 전체 삭제 영향 변경도 재확인. 사라진 대상은 등록 실패 안내·내용 보존·다른 대상 선택. 공개 상세는 대상 삭제 안내 후 지도 이동 제공 | [DB 명령·잠금 계약](data-model.md) |

| DEC-09 | 관리자 이메일/비밀번호, 사전 생성/allowlist만. 만료 시 변경 거절·초안 유지·재로그인, 작업 자동 재실행 없음. 권한 회수는 다음 요청부터 거절 | [ADR-0003](adr/0003-identity-and-authorization.md); 실제 운영자 명단 필요 |
| DEC-10 | 신규 부스는 연 시점 이후 알림, 같은 브라우저는 완료 cursor 복구, 4초/건, 로그는 첫 버전에서 자르지 않음. 현재 이름 표시, 삭제된 등록은 건너뜀. 동시에 제출하면 커밋 직렬 순서 | [ADR-0005](adr/0005-state-sync-and-announcements.md); 4초 노출·복구·삭제 제외 정책 채택 |

## 무료 운영 추가 조건

- 월0원·기존 자원 없음·행사 집중 사용은 사용자 합의다. [PRD 운영 제약](../1-prd.md#10-운영비-제약)에 반영한다.
- 휴면 후 운영자 수동 재개를 허용한다. 재개 전 조회·등록 중단을 운영 조건으로 명시한다.
- 무료 자원 소진 시 유료 전환 없음, 사진 용량 부족은 사진 제거 후 명시적 재등록 가능. 실패 사진을 빼고 자동 성공하지 않는다.
- 임시/처리/첨부 사진 크기·용량·수동 백업은 [사진](media.md)과 [운영](operations.md)의 기본값을 따른다.
- 부스 DB 로그는 계속 유지하고 개인정보 원문을 담지 않는다. 수신 cursor와 표시 완료 cursor는 분리한다.

- 행사 전후·DB 변경 전·변경이 있었던 주의 수동 백업과 마지막 성공 백업 이후 손실 가능성을 수용한다. [백업 기록·복원](backup.md)을 따른다.
