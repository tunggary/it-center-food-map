# ADR-0004: 카카오 장소 ID와 직접 작성한 산책 경로를 사용한다

- **상태**: 승인됨 (2026-10-13 사용자 결정 및 보완 계획 채택; 구현·성능 검증과 별개)
- **날짜**: 2026-10-13
- **드라이버**: R4·C1·C2·D6·D8 ([드라이버](../drivers.md))
- **설계 질문**: Q3 — 실제 장소 선택과 산책 경로를 무엇으로 구현할까?
- **관련**: ADR-0002, DEC-01, A2·A7

## 컨텍스트

장소는 실제 지도 검색/선택 결과여야 한다. 산책코스에는 이름·경로가 필요하지만 자동 길찾기는 확정 요구가 아니다. 거리·시간은 지도 서비스가 제공할 수 있을 때만 표시한다. 국내 장소 중심이며 삼성역 밖 등록도 허용한다.

## 공식 자료에서 확인한 사실

2026-10-13 확인. API 계정을 실제 호출하거나 모바일에서 시험한 결과는 아니다.

- [카카오 Local REST](https://developers.kakao.com/docs/ko/local/dev-guide)는 장소 검색 결과에 ID·이름·주소·경도/위도를 제공한다.
- [카카오 Web API](https://apis.map.kakao.com/web/documentation/)는 marker/polyline을 제공하고, [공식 거리 샘플](https://apis.map.kakao.com/web/sample/calculatePolylineDistance/)은 직접 그린 선의 길이를 계산한다. 샘플의 시간 추산 코드를 공식 보행 경로 소요 시간으로 해석하지 않는다.
- [네이버 Directions 15](https://api.ncloud-docs.com/docs/ai-naver-mapsdirections15-driving)는 자동차 경로 API다. 이 문서로 자동 보행 길찾기 지원을 입증할 수 없다.
- SDK의 지도 그리기와 자동 경로 탐색은 다른 기능이다. 조사 범위에서 확보되지 않은 보행 경로 API가 있다고 가정해 설계하지 않는다.

## 검토한 대안

| 대안 | 얻는 것 | 치르는 것 |
| --- | --- | --- |
| 카카오 Web + Local 검색 + 직접 경로 | C2 장소 ID를 한 제공자에서 확보, 직접 경로를 앱 데이터로 보관 | D6 모바일 점 입력 UX 개발·검증 필요, 도로 자동 보정 없음 |
| 네이버 Web 지도 + 지역 검색 + 직접 경로 | 국내 지도·경로 표시 가능 | 검색/식별 계약을 별도 검증해야 함; 이번 요구를 더 잘 충족할 확인된 이점 없음 |
| 지도 + 별도 보행 라우팅 제공자 | 사용자가 경유지만 입력해 보행 경로 생성 가능 | 별도 계약·비용·장애·경로 저장 조건, PRD에 없는 의존성 |

## 결정

카카오 지도를 사용한다. 검색은 서버 Local REST로 호출하고 결과마다 세션에 묶인 서명 선택 토큰을 발급한다. 토큰은 provider/place_id/name/좌표/주소·만료·세션 식별자를 포함하며 서버 키로 서명한다. 기본 유효 기간30분; 만료 시 입력은 유지하고 재검색/재선택한다.

브라우저가 보낸 임의 이름·좌표는 장소 생성에 쓰지 않는다. 지도 선택은 앱이 검색 결과로 그린 실제 장소 마커에 연결한다. 바탕 지도의 모든 POI를 클릭해서 ID를 얻을 수 있다고 가정하지 않는다. 기존 대상 재등록은 저장된 target ID로 처리하여 외부 검색 장애와 분리한다.

산책코스는 지도 중앙 십자선에 점 추가·취소·완료 버튼으로 LineString을 만든다. 모바일에서 우클릭/더블클릭을 완료 필수 동작으로 쓰지 않는다. 경로 전체는 사용자가 작성한 데이터로 저장하고 시작점은 첫 좌표에서 도출한다. 자동 스냅/보행 안전성 검증은 제공하지 않는다.

참고 거리는 SDK의 선 길이로 표시할 수 있으나 실제 보행 거리/예상 시간을 보장하지 않는다. 서버는 좌표로 선 길이를 재계산해 클라이언트 수치를 신뢰하지 않으며, 시간은 첫 버전에서 표시하지 않는다. 관리자 정정은 같은 편집기를 사용하며 기존 target ID를 유지한다.

## 근거

C2를 만족하면서 추가 라우팅 계약 없이 끝낼 수 있다. 실제 장소는 제공자 ID로 통합하고 직접 만든 경로는 고유 코스로 취급하여 R4에 맞는다. 사용자가 직접 경로 작성을 선택하고 자동 도보 길찾기 제외를 확정했다.

## 결과

- **좋아진 것**: 장소 중복 기준 명확, 경로 수정에도 기존 등록 유지, 외부 API 호출은 검색 단계에 국한.
- **감수할 것**: 코스 작성에 손이 가고 실제 보행로에 맞게 사용자가 점을 추가해야 한다. 지도/검색 품질과 사용 정책에 의존한다.
- **함정**: GeoJSON [경도,위도]와 SDK LatLng 인수 순서 혼동, 카테고리를 지도 제공자의 분류로 강제, 선 길이를 실제 도보 경로/소요 시간으로 표기, 임의 핀을 실제 장소로 신뢰.
- **새로 생긴 설계 숙제**: 모바일 입력 기술 검증, 허용 도메인·API 사용 권한·쿼터·선택 장소의 최소 메타데이터 저장/갱신 조건 확인. A7로 추적한다.

## 검증

삼성역 안/밖의 실제 장소 검색, 같은 ID 두 명 동시 생성, 토큰 변조/만료, 두 모바일에서 점 추가·취소·완료·정정·코스 전환, 유사 코스 별개 집계를 확인한다. 장소 메타데이터 저장/표시 조건은 실제 앱 출시 전에 확인한다.

## 재검토 트리거

A2 자동 보행 길찾기 필수, 직접 경로 UX 실패, 지도 저장/표시 조건이 모델과 충돌, 실제 앱 쿼터/사용 권한 확보 실패. 이 경우 제공자 검토부터 다시 하며 경로 요구를 임의 삭제하지 않는다.

## 변경 이력

- 2026-10-13: 무료 운영 조건에서도 카카오 장소 검색·직접 경로 입력 결정을 유지했다. 앱 권한/쿼터·저장 조건은 출시 전 확인하며 무료라는 이유로 경로 요구를 삭제하지 않는다. 문서 위치를 설계 폴더로 옮겼다.

- 2026-10-13: 사용자가 남은 제품·운영 정책과 상세 보완 계획을 채택해 승인됨으로 전환했다. 이는 구현/성능 통과가 아니다. 용량 예약·백업 실행/복원 계약은 [용량](../storage-accounting.md)·[백업](../backup.md)에 연결했다.
