# ADR-0006: 작은 사진을 검증한 뒤 등록 연결을 통해 공개한다

- **상태**: 승인됨 (2026-10-13 사용자 결정 및 보완 계획 채택; 구현·성능 검증과 별개)
- **날짜**: 2026-10-13
- **드라이버**: R2·R5·R6·D5·D8·C4 ([드라이버](../drivers.md))
- **설계 질문**: Q6·Q9 — 무료 Edge에서 사진 실패·용량·삭제를 어떻게 관리할까?
- **관련**: [사진 수명주기](../media.md), [운영](../operations.md)

## 컨텍스트

사진 0~3장, 실패 시 입력 유지, 삭제 시 공개 제외가 요구다. 무료 Storage는 1GB, Edge CPU는 요청당 2초이고 Sharp를 지원하지 않는다. DB와 객체 저장소의 원자적 commit은 없다.

## 검토한 대안

| 대안 | 얻는 것 | 치르는 것 |
| --- | --- | --- |
| 브라우저 축소 + WASM 서버 검증 + private 응답 | C4 작은 파일, D8 무사진 등록 격리, R2 새 접근 철회 | WASM 런타임 시험, proxy 호출/egress, 청소 필요 |
| 원본 공개 버킷 + URL | 구현·전송 단순 | C4 용량·전송 증가, 삭제 후 URL/캐시 문제 |
| 브라우저 변환만 믿고 공개 | 서버 CPU 절약 | 악성 클라이언트가 검증 우회, R6 업로드 방어 약화 |
| 유료 이미지 서비스 | 처리·캐시 운영 위임 | C4 위반 |

## 결정

브라우저에서 JPEG 512KiB·2MP 이하로 만들고 private raw 경로에 signed upload한다. Edge의 magick-wasm은 한 장씩 decode·메타데이터 제거·재인코딩·썸네일 생성을 수행하고 서버만 쓸 수 있는 새 불변 key에 저장한다. ready 이후에만 DB 명령에서 favorite와 연결한다.

사진 GET은 현재 살아 있는 favorite 연결을 확인한 후 바이트를 반환하며 no-store다. 공개 URL이나 signed download URL을 배포하지 않는다. 삭제는 연결 철회와 cleanup 예약을 같은 트랜잭션에 넣고, 물리 객체는 재시도 가능한 청소로 제거한다. 사진 크기·용량 예약·lease·만료는 사진 문서를 따른다.

## 근거

선택 사진을 등록 트랜잭션에서 분리하면 D8을 지키며 저장 실패를 명확히 처리할 수 있다. 브라우저와 서버의 작업을 나눠 C4/CPU 제약을 맞추고 서버 검증은 유지한다. 큰 원본 보관은 요구가 아니다.

## 결과

- **좋아진 것**: 저장·전송량 제어, 부분 첨부를 성공으로 오인하지 않음, 삭제 후 새 접근 차단.
- **감수할 것**: 원본 화질 미보관, 사진 변환 지연, private proxy 호출/전송량, 수동 사진 백업.
- **함정**: Sharp를 Deno에서 그대로 사용, 클라이언트 MIME 신뢰, 디코딩 전 픽셀 검사 누락, 늦은 finalize로 삭제 파일 복구, 청소 예약만으로 용량 반납, signed raw 권한의 늦은 재사용.
- **새로 생긴 설계 숙제**: Q9 객체 사전 추적·lease 소유 검사·만료 청소·업로드 권한 만료 후 재청소를 사진 문서에 해결했다. 최대 파일 G2 시험은 구현 첫 게이트다.

## 검증

2MP 사진의 WASM CPU·메모리·번들 크기, raw/final/thumb 각 단계 실패, 3장 슬롯 경합, 삭제 후 GET 404, 타인 자산 연결, 청소와 등록 경합, 용량 초과 시 초안 보존을 검증한다.

## 재검토 트리거

G2 제한 미충족, HEIC 원본/고화질 필수, 용량/egress 소진, 엄격한 물리 삭제 시간 요구. 유료 전환이나 무검증 업로드로 조용히 해결하지 않는다.

## 변경 이력

- 최초안: Node/Sharp와 큰 원본 사전 업로드.
- 2026-10-13: 무료 Edge 제약으로 브라우저 축소 + magick-wasm 선택, 작은 사진 상한·DB 용량 예약·수동 백업 반영. 비공개 연결 검사 원칙은 유지한다.

- 2026-10-13: 사용자가 남은 제품·운영 정책과 상세 보완 계획을 채택해 승인됨으로 전환했다. 이는 구현/성능 통과가 아니다. 용량 예약·백업 실행/복원 계약은 [용량](../storage-accounting.md)·[백업](../backup.md)에 연결했다.
