# ADR-0001: 정적 앱과 관리형 무료 백엔드를 분리한다

- **상태**: 제안됨
- **날짜**: 2026-10-13
- **드라이버**: D1·D7·D8·C1·C4 ([드라이버](../drivers.md))
- **설계 질문**: Q5 — 월0원·100명·행사 이후 참여를 어떤 구성으로 지원할까?
- **관련**: [구현 스택](../stack.md), [운영](../operations.md)

## 컨텍스트

무료만 사용·기존 자원 없음·행사 집중 후 가끔 참여가 사용자 답변으로 확정됐다. 기존 유료안은 이 제약을 만족하지 않는다. 정적 지도 앱은 검색엔진용 서버 렌더링이 핵심이 아니며, 쓰기 정합성은 PostgreSQL에 모을 수 있다.

## 검토한 대안

| 대안 | 얻는 것 | 치르는 것 |
| --- | --- | --- |
| Vite/React Pages + Supabase Free | C4 무료 범위, D7 서버 운영 최소화, PostgreSQL 유지 | 브라우저/API 출처 분리, 무료 휴면·용량·CPU 제한 |
| Next.js + 무료 서버리스 호스팅 | 기존 프레임워크 구조 유지 | 공급자별 Node 호환·실행량 제한, Vercel Hobby 용도 적합성을 전제할 수 없음 |
| Cloudflare Workers/D1 중심 | 단일 공급자·가벼운 SQL | 기존 PostgreSQL 모델·인증·사진 검증을 더 크게 재설계; worker CPU 제한 |
| 단일 자체 서버 | 런타임/백업 통제 | 기존 서버가 없으므로 C4에 맞는 지속 운영 자원 없음 |

## 결정

React/Vite 정적 앱을 Cloudflare Pages Free에 배포하고, Supabase Free의 PostgreSQL·Edge Functions·Storage·관리자 Auth를 사용한다. Edge는 서버 검증, SQL RPC는 트랜잭션, Data API 공개 read RPC는 조회를 담당한다. 초기 구현에 Next.js/Drizzle/pg/상시 서버를 넣지 않는다. SQL migration으로 DB 함수를 관리한다.

## 근거

C4를 지키면서 관계형 원장과 R1~R6를 보존할 수 있다. 요청마다 Edge를 거치지 않는 공개 읽기와 정적 호스팅으로 제한 자원을 아낀다. 무료 한도 안에서 가능한 구성이며 무기한 무제한 가용성 보장은 아니다.

## 결과

- **좋아진 것**: 유료 고정비 없음, FE/API/DB 책임 명확, 같은 DB에 업무 규칙 집약.
- **감수할 것**: 별도 출처 자격 전달, SQL 함수 테스트/배포 필요, 휴면과 수동 백업 운영. 수동 재개 허용은 아직 가정이다.
- **함정**: 무료 API 횟수를 성능/egress 무제한으로 해석, Pages에 Next 서버 기능을 배포, preview에 운영 DB 연결, DB백업을 사진백업으로 오인.
- **새로 생긴 설계 숙제**: Q2 자격 전달→ADR-0003, Q4 호출/전송량→ADR-0005, Q6 이미지 런타임→ADR-0006. 운영 기본값은 연결 문서에 명시.

## 검증

G1 무료 실행 경계·G2 WASM·G4 100명 성능과 egress를 실제 측정한다. DB/사진 복원 연습을 하고 무료 제한 초과를 자동결제로 해결하지 않는다.

## 재검토 트리거

항상 즉시 접속이 필수라 휴면 수동 재개를 수용할 수 없음, 실제 한도/지연 시험 실패, 사진량이 무료 예산 초과, 외부 무료 정책 변경. 이를 발견하면 구조를 재검토하고 요구를 조용히 낮추지 않는다.

## 변경 이력

- 최초안: Next.js/Vercel Pro/Supabase Pro, 소액 유료 가정으로 제안됨.
- 2026-10-13: 사용자 무료 조건으로 같은 제안 ADR 개정. 비용 제약은 합의, 상세 운영/성능은 검증 전. 기존 승인 ADR 대체 없음.
