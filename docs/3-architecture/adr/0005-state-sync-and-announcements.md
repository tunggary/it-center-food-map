# ADR-0005: Data API를 직접 조회하고 부스 알림은 DB에서 재생한다

- **상태**: 제안됨
- **날짜**: 2026-10-13
- **드라이버**: R5·D1·D2·D4·D5·D7·C4 ([드라이버](../drivers.md))
- **설계 질문**: Q4·Q7 — 무료 한도에서 5초 갱신과 순서 알림을 어떻게 지킬까?
- **관련**: [동기화](../synchronization.md), [사용량](../operations.md)

## 컨텍스트

동시 100명, 다른 화면 5초 반영, 알림 대기 허용이 요구다. 이전 안의 2초 poll을 Edge를 거쳐 실행하면 100명 8시간에 144만 회로 무료 Edge 월 50만 회를 넘는다. 무료 Realtime도 초당 100메시지여서 100명에게 변경을 전달할 때 여유가 없다.

## 검토한 대안

| 대안 | 얻는 것 | 치르는 것 |
| --- | --- | --- |
| 공개 Data API revision 직접 2초 조회 | C4 Edge 실행 없음, D5 재연결 단순, 기존 DB로 해결 | 초당 50조회 DB 부하와 egress, 주기적 탐지 지연 |
| Supabase Realtime + 영속 event | 즉각 변경 신호, 유휴 조회 감소 | 무료 초당 100메시지·구독자 수 제한, 누락 복구 조회 별도 |
| Edge 경유 poll | 기존 API 일원화 | C4 무료 함수 호출 한도에 비효율 |
| 별도 SSE/WebSocket 서버 | 세밀한 전달 제어 | D7/C4 추가 런타임·재연결·운영 책임 |

## 결정

2초마다 Data API의 read_revision을 직접 읽고 변경 시 화면 snapshot을 조회한다. 모든 공개 RPC는 읽기 전용 projection이고 권한을 제한한다. 사진/부스 event를 revision 응답에 싣지 않는다. 초기·재연결·전경 복귀는 즉시 snapshot을 읽는다.

부스 신규 등록 event는 favorite와 같은 트랜잭션에 기록하고 전역 revision 순서로 읽는다. 알림 수신 cursor와 표시 완료 cursor를 분리하며 고정 watermark까지 페이지를 읽는다. 새 부스는 현재 시점 이후, 같은 브라우저는 완료 cursor부터 재생한다. 삭제 등록은 건너뛰고 현재 이름을 표시하는 DEC-10 기본안이다.

## 근거

5초 요구는 초저지연 연결을 강제하지 않는다. 무료 Data API는 요청 횟수 무제한이지만 DB/egress는 유한하므로 운영 예산과 부하 시험을 함께 둔다. 알림 원장을 전송 방식과 분리하면 누락·순서 문제를 독립적으로 처리할 수 있다.

## 결과

- **좋아진 것**: Edge/Realtime 한도를 소비하지 않는 단일 DB 경로, 복구·순서 보장, 알림 대기와 화면 갱신 분리.
- **감수할 것**: 작은 반복 조회와 snapshot 전송 비용. 무한 데이터와 상시 접속을 무료로 보장하지 않는다.
- **함정**: 무료 API를 무한 CPU로 오해, 페이지 수신 시 완료 cursor 저장, watermark로 미표시 event 건너뛰기, revision을 Number로 변환, 복원 후 과거 cursor 고착.
- **새로 생긴 설계 숙제**: Q7 페이지·tombstone·현재 이름·복원 epoch·중복 재생 경계를 동기화 문서에 해결했다. 사업 정책은 DEC-10 제안으로 구분한다.

## 검증

100명 부하에서 poll + snapshot + DOM의 5초 반영, 100건 알림 대기 중 지도 갱신, 늦은 응답·네트워크 단절·페이지 처리 중 종료·DB 복원 epoch를 시험한다. 실제 egress를 계량한다.

## 재검토 트리거

직접 DB 읽기가 목표 지연을 충족하지 못함, 월 egress 예산 초과, 초저지연 요구, 무료 한도 변경. 이때 변경 묶음·데이터 차이 전송·대체 호스팅을 비교하고 현재 5초 요구를 자동 완화하지 않는다.

## 변경 이력

- 최초안: Next 앱 경유 revision poll + DB event.
- 무료 전환 대화 중 Realtime을 잠정 추천했다.
- 2026-10-13: 초당 메시지 제한을 확인해 Realtime 추천을 철회하고, Edge 없이 Data API 직접 조회로 수정했다. 영속 알림 원장은 유지한다.
