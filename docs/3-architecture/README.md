# 무료 운영 아키텍처·세부 설계

[프로젝트 진행](../README.md) · [PRD](../1-prd.md) · [사용자 스토리](../2-user-story.md) · [용어](../../GLOSSARY.md)

최종 갱신: 2026-10-13. **제품 정책·기술 설계 확정, 구현·성능 검증 전**. 예산은 월 0원, 기존 유료 자원 없이 새 구성, 행사에 사용이 집중되고 이후 가끔 참여한다는 사용자 답변을 반영했다. 사용자가 개인 프로젝트로 운영하고 Vercel을 사용하기로 정해 정적 배포처를 Vercel Hobby로 변경했다. 남은 정책도 사용자 협의로 [확정](policies.md)했고 사진 용량·백업의 물리 설계와 API를 보완했다. 정적 준비 페이지 배포는 [배포 기록](../deployment.md)에 있다.

## 결론

**React/Vite 정적 앱 + Vercel Hobby + Supabase Free(PostgreSQL·Edge Functions·Storage·관리자 Auth) + 카카오 지도**를 사용한다.

- 공개 조회와 변경 번호 확인은 **Data API의 읽기 전용 RPC**를 직접 호출한다. 2초 조회마다 Edge Function을 실행하지 않는다.
- 참여자 자격·검색·쓰기·사진은 Edge Functions에서 검증한다. 여러 데이터 변경은 **DB 함수 한 번 = 트랜잭션 한 번**으로 처리한다.
- 참여자는 무작위 브라우저 자격을 보유하며, 관리자만 Supabase Auth로 로그인한다. 일반 참여자에게 회원가입을 요구하지 않는다.
- 무료 Realtime의 초당 메시지 한도 때문에 **Realtime은 사용하지 않는다**. 부스 알림은 등록과 같은 트랜잭션에 저장한 기록을 순서대로 읽는다.
- 사진은 브라우저에서 작게 변환하고 Edge의 WASM으로 재검증·정규화한다. 비공개 저장소와 현재 등록 연결 검사로 삭제 이후 새 접근을 막는다.
- 무료 한도/휴면은 무한 가용성을 의미하지 않는다. 휴면 수동 재개와 수동 백업의 손실 범위는 **사용자 확정 운영 조건**이다. 자동 유료 전환은 하지 않는다.

## 완료의 의미

기술 선택·책임 경계·API·데이터 흐름·실패 처리·운영 기본값을 문서로 정했다. 설계 확정은 제품 동작 검증·무료 한도 내 무기한 운영 보장·실제 행사 정보 입력 완료를 뜻하지 않는다. 구현자는 문서의 기본안으로 시작하고 [검증 게이트](verification.md)를 통과해야 한다.
