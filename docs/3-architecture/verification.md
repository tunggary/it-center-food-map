# 검증·구현 순서

[설계 목차](README.md) · [스토리·QA 연결](traceability.md) · [기존 QA](../2-user-story.md)

아래는 실행할 계획이다. 제품 코드가 없으므로 성능/기능 통과로 기록하지 않는다. 원본 QA의 미실행44·판정 보류21을 유지한다.

## 먼저 통과할 기술 게이트

| 게이트 | 수행 내용 | 통과/실패 기준 |
| --- | --- | --- |
| G1 무료 실행 환경 | Vite/React 빌드, Deno 공통 타입, SQL RPC 권한, Vercel 직접 링크 | 유료 기능 없이 최소 읽기/쓰기 가능, 비밀 번들 노출0 |
| G2 사진 | magick-wasm CLI 배포 번들·초기화·최대2MP JPEG 처리 | 실제 Edge CPU≤1.5초·메모리≤192MB 목표, 공급자 2초/256MB 상한 미초과. 형식/크기 우회 거절 |
| G3 현장 입력 | iPhone Safari/Android Chrome 경로 점 추가·사진 선택·방향 | 실제 이름/경로 저장·HEIC 처리 안내·정상 JPEG 완결, Web Locks/저장소 초기화 확인 |
| G4 공개 조회 성능 | 실제 무료 DB의 read_revision + snapshot +100명 | 별도 정상 부하에서 3초/2초/5초를 실측. 무료 API 무제한만 보고 통과시키지 않음 |

G2 실패 시 사진 기능을 통째로 제외하거나 무검증 업로드로 통과시키지 않는다. 서버 입력 크기/전처리 방식을 조정해 다시 검증하고 ADR-0006 변경 이력을 남긴다. G4 실패 시 현재 무료 구성이 요구를 충족했다고 배포하지 않는다.

## DB·권한·재시도

- 실제 PostgreSQL에 FIX-01을 넣고 조건별 건수, 1·1·3, 팀 정정/분류 수정/삭제 이후 결과를 검사한다. SQL mock으로 대체하지 않는다.
- 동일 identity/target 20동시 요청, 같은 키/다른 키, 같은 키/다른 payload, 신규 COURSE 응답 유실을 시험한다. 성공 신규등록·코스·알림이 정확히 의도한 수여야 한다.
- 동일 장소 ID 동시 생성, 원작성자의 코스 등록 삭제, 마지막 등록 삭제 후0건 제외, 중단 카테고리 기존 편집/신규 선택을 확인한다.
- 삭제 preview 후 등록 추가·삭제·편집, 관리 팀 정정과 참여자 등록 경합, asset 청소와 연결 경합을 실행한다. 부분commit/잘못된 권한/미확인 전체삭제가 없어야 한다.
- 브라우저 anon/authenticated key로 내부 table/gateway 쓰기 호출을 직접 시도해 거절을 확인한다. SQL 함수 EXECUTE와 search_path를 자동 검사한다.
- 토큰 변조·만료·저장소 삭제·두 탭 최초 발급·동명 참여자·관리자 JWT만 있고 allowlist 없음·권한 회수·서비스 키 FE 유출 검사를 포함한다.
- 사진4장 slot 동시 연결·타인asset·MIME 위조·초대형픽셀·업로드/변환/DB실패·lease만료·late completion·삭제 후 URL404를 확인한다.

## 연결·알림

두 참여자 브라우저와 부스·관리자를 분리한다. 네트워크 중단·응답 유실·늦은 필터 응답·초기 API실패·재연결을 주입하고 마지막 결과/초안이 유지되는지 확인한다.

100건 알림을 쌓고 지도 갱신과 무관하게 순서대로 처리되는지 확인한다. watermark pagination 중 끊김·표시 전 종료·표시 직후 종료·대기 등록 삭제·이름 수정·새 부스 방문·저장소 복원으로 revision 감소를 시험한다. 현재 살아 있는 신규 등록 누락0, 이미 삭제된 사진/내용의 재노출0을 목표로 한다. crash 후 마지막1건 중복 재생은 명시된 허용 범위다.

## 부하·측정 기준 제안

PRD 수치: 동시100명, 첫 지도+랭킹3초, 사진 없는 완료2초, 다른 화면반영5초, 첫 사용자 등록2분. 구체 조건은 DEC-12 제안이므로 확정 전 최종 합격 판정과 구분한다.

- 기준 데이터 1,000대상/10,000등록/30팀/10카테고리. 파일 최대 경계 시험과 현실적인 사진량은 따로 준비한다. 대용량 누적 데이터를 실제 무료 운영 예상치로 단정하지 않는다.
- 정상 네트워크 가정 RTT≤100ms·하향≥10Mbps·상향≥5Mbps·인위 손실0. cold/warm 각각100표본. 첫 표시/완료는 P95와 최대값을 함께 기록하고 목표는 P95≤3초/2초. 5초 타 화면 반영은 모든 정상 연결 관측 표본에서 만족해야 한다.
- 100참여자+부스1+관리1, 전경 상태 30분. 로컬 stress는 초당5등록 및 시작100건 동시 제출을 별도로 수행한다. 실서비스 시험은 quota 예산을 먼저 계산하고 소량→100명 정상 흐름 순서로 올린다.
- 정상 행사 예산 시험은 [운영 예시](operations.md)의 등록/사진수·snapshot 크기와 실제 행사 조건 둘 다 기록한다. 압축 body, 프로젝트 egress, Edge 호출, DB 크기/잠금대기를 함께 측정한다.
- 처음 쓰는5명이 도움 없이 사진 없는 장소 등록을 각각2분 내 완료하는 것을 제안한다. 실제 관찰 없이 자동화 스크립트 시간으로 대체하지 않는다.
- 지도 SDK/외부 검색 지연을 end-to-end 측정에서 빼지 않는다. 서버 응답만 2초여도 상세가 늦으면 등록2초 통과가 아니다.

## 운영 검증

무료 한도 접근을 낮춘 테스트 설정으로 재현해 사진 누락 없이 오류/재시도 가능한지 확인한다. 공급자 실제 용량을 채워 장애를 일으키는 시험은 하지 않는다. 휴면/서비스중지와 유사한 API오류를 주입하고 수동 재개 절차는 테스트 프로젝트에서 확인한다.

로컬에서 DB+사진+관리자 재생성·identity 관계 복원·epoch변경까지 연습하고 마지막 성공 백업 시점/복원 시간을 기록한다. 정적 앱 rollback만으로 데이터가 되돌아간다고 간주하지 않는다.

## 구현 순서

1. G1~G3 기술 검증, 실제 지도 앱 도메인/쿼터·저장 조건 확보. 이 결과로 입력 제한/운영 가정을 검토한다.
2. schema/권한/RPC + FIX-01/동시성 테스트. 공개 탐색과 브라우저 identity, 무사진 첫 등록→상세→본인 편집을 구현한다.
3. 실제 장소·코스·관리자 정정/전체삭제, snapshot/부스 cursor를 구현하고 역할별 QA를 실행한다.
4. 사진 처리·private 응답·청소·용량 계량을 추가하고 실패 주입을 수행한다.
5. 100명/현장 기기·네트워크 측정, 무료 한도 여유·백업 복원·운영자 계정 점검 후 배포한다.

각 구현 작업 종료 시 프로젝트 README의 실제 상태와 관련 QA 실행 근거를 갱신한다. 운영 날짜·팀 목록·사전참여 정책 미확정을 설계 가정으로 덮어쓰지 않는다.
