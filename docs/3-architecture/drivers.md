# 참여형 최애 지도 — 아키텍처 드라이버

- **입력**: [PRD](../1-prd.md), [사용자 스토리 전체](../2-user-story.md), 역할별 4개 문서·QA 4개 문서·[DEC-01~12](../2-user-story/decisions.md)
- **최종 갱신**: 2026-10-13
- **상태**: 설계 제안. 제품 요구의 확정 여부와 기술 제안의 채택 여부를 구분한다. 구현·성능 검증은 아직 수행하지 않았다.
- **현재 구조**: 문서만 있고 애플리케이션·DB·배포는 없다. 첫 설계 때 기존 ADR이 없었으며 이번에 제안 ADR 6개를 무료 조건으로 개정한다.
- **설계 범위**: PRD의 참여자·부스·관리자 기능 전체를 수용한다. 첫 버전 범위를 임의로 축소하지 않는다.

## 2. 우선순위

R1~R6 및 C1~C4 준수 > D5 > D2·D4 > D1·D6 > D7.
D8은 외부 장애 때 D5를 지키기 위한 도출 기준이다. 불변 규칙을 속도·비용과 교환하지 않는다. 100명 규모에서 운영 구성 요소를 늘리기보다 DB 정합성과 현장 실패 처리를 우선한다.

## 3. 현재 구조와 붕괴점

가장 단순한 `브라우저 → 앱 → DB`에서 다음 문제가 생긴다.

| 붕괴점 | 성격 | 필요한 대응 |
| --- | --- | --- |
| 등록 행에 장소·팀·닉네임까지 복사 | 정합성 | 대상/참여자/등록 분리, 현재 참여 정보 JOIN |
| 버튼 비활성화만으로 중복 방지 | 정합성 | DB 유일성 + 명령 재시도 식별 |
| 등록을 저장한 뒤 메모리 알림 생성 | 유실·순서 | 같은 트랜잭션에 영속 알림 기록 |
| 알림 재생 완료 후 화면 새로고침 | 신선도 | 상태 동기화와 알림 재생을 분리 |
| 매 요청 지도 검색·사진 처리 | 외부 장애 전파 | 장소 선택 증명, 업로드 사전 완료, 짧은 DB 트랜잭션 |
| 삭제 확인 후 새 등록 발생 | 동시성 | 대상 변경 버전 확인, 트랜잭션 안에서 재검증 |
| 사진 공개 URL 배포 후 DB만 삭제 | 삭제 일관성 | 비공개 객체 + 현재 연결을 확인하는 사진 응답 |
| 별도 서버·캐시·메시지 브로커 선도입 | 운영 복잡성 | 단일 앱·PostgreSQL·객체 저장소로 시작 |

## 5. 구조 요약

[설계 목차](README.md)와 [스택](stack.md)에 최종 구조를 모았다.

```text
휴대폰/부스/관리자 → Cloudflare Pages의 React/Vite 정적 앱
  ├─ Kakao Web SDK: 실제 장소·직접 경로
  ├─ 공개 read RPC → Supabase Data API → PostgreSQL
  ├─ 참여자 bearer / 관리자 JWT → Edge Functions → gateway RPC 한 번
  ├─ signed upload → private Storage → WASM finalize
  └─ 사진 GET → 현재 favorite 연결 검사 → private 객체 응답
PostgreSQL: 도메인 원장 + revision + commands + 부스 event + cleanup
Supabase Cron: 소량 객체 청소 / 운영자: 수동 백업·휴면 재개
```

Redis·전용 API 서버·Realtime·PostGIS·유료 이미지 변환은 넣지 않는다. 2초 변경 확인은 Edge를 거치지 않고 공개 읽기 RPC만 호출한다. DB/전송량 비용은 여전히 관리해야 한다.

## 7. 미해결 질문 · 가정

### 구조를 가르는 조건

- **A1 비용: 합의 완료.** 사용자 답변은 무료만·기존 자원 없음·행사 집중 후 가끔 사용이다. 유료안은 채택하지 않는다. C4 추가, ADR-0001·0003·0005·0006 개정.
- **A2 산책 입력:** 직접 점을 찍는 경로를 구현 기본안으로 둔다. 자동 보행 길찾기는 포함하지 않는다. 별도 명시 답변 전이므로 가정 표시 유지. ADR-0004.
- **A3 측정 조건:** 동시100명·3/2/5초·첫 사용2분은 PRD 확정. 데이터량/지속 시간/표본/네트워크는 [검증 계획](verification.md)의 제안 기준이며 실제 행사 조건 확인 후 판정한다.
- **A8 휴면:** 수동 재개 허용 여부를 사용자에게 질문한 상태. 답변 전에는 무료 우선·운영자 수동 재개로 설계하되 항상 즉시 사용 가능을 보장하지 않는다. 거절 시 ADR-0001 재검토.

### 결정별 기본값과 운영 입력

- **A4 관리자:** 사전 준비한 Supabase Auth 이메일/비밀번호 + allowlist. 실제 명단/계정은 배포 전 운영 입력이다.
- **A5 제품 정책:** [DEC별 기본안](policies.md)은 구현 선택을 명시한 제안이다. PRD의 불변 규칙과 구분하며 원본 QA 보류를 자동 해제하지 않는다.
- **A6 복구:** 무료 자동 백업 없음. 행사 전후/migration 전 및 변경 있는 주의 수동 백업, 마지막 성공 백업까지 복원. RPO24h/RTO2h 가정 철회. 자세한 절차는 [운영](operations.md).
- **A7 지도:** 실제 앱 키/도메인/권한·쿼터·최소 장소 메타데이터 저장 조건은 출시 전 확인한다. 공식 SDK 조사와 계정 권한 확보는 다르다.

기술 질문은 선택된 기본안으로 닫았다. 알려지지 않은 행사일·팀 목록·네트워크를 임의로 만들지 않는다. 모든 기술 선택이 성능 시험에 이미 통과했다는 뜻은 아니다.
