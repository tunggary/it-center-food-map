## URL과 상태

| 경로 | 표시/상태 |
| --- | --- |
| `/` | 삼성역 중심 지도·상단 한 줄 랭킹·하단 등록 버튼 |
| `/rankings?team=&category=` | 팀/분류 필터·공동 순위·더 보기 |
| `/targets/:id?team=&category=` | 조건별 상세, 전체 보기, 본인 등록 관리 |
| `/register`, `/courses/new` | 대상 선택/코스 준비·등록 폼·최초 참여 정보 |
| `/me/favorites`, `/me/profile` | 본인 목록/닉네임 수정, 팀은 운영자 정정 안내 |
| `/booth` | 전체 팀 카테고리별 랭킹·핀 필터·상단 순서 알림 |
| `/admin/login`, `/admin/*` | 인증·목록 관리·정정·삭제 영향 확인 |

React Router browser history를 쓰고 Vercel의 `vercel.json`에 SPA rewrite를 설정한다. 구현 시 `/`, `/rankings`, `/targets/:id`, `/register`, `/courses/new`, `/me/:path*`, `/booth`, `/admin/:path*`만 `/index.html`로 연결한다. 직접 상세 링크/새로고침도 index.html을 받아야 하며 JS/CSS/없는 asset까지 HTML로 바꾸지 않는다. API는 Supabase URL로 명시적으로 호출한다.

서버 데이터는 Query, 필터는 URL, 작성 초안은 작성 화면 상태, 자격만 localStorage다. 서버 count를 optimistic +1로 확정하지 않는다. 성공 응답과 최신 상세를 확인한 뒤 완료 표시한다. 새 등록의 category가 원래 필터와 달라 안 보이면 상세 전체 보기로 전환하되 돌아갈 필터는 보존한다.

## 지도·실제 장소

카카오 Web SDK는 singleton loader로 한 번 로드한다. 검색은 Edge Local REST를 사용하고 앱이 그린 검색 결과 marker를 선택한다. 지도 바탕의 모든 POI 클릭에서 ID를 얻을 수 있다고 가정하지 않는다. 임의 핀/이름으로 PLACE를 등록하는 입력은 없다.

검색은 입력 후 300ms debounce, 요청 취소, 서버 페이지 크기 15, 결과 없을 때 재검색. 지도 중심은 검색 우선순위에만 사용하고 다른 지역을 차단하지 않는다. 선택된 서버 결과를 서명 토큰으로 보관하고 작성 폼에는 사람이 읽을 이름·주소를 보여준다. 30분 만료 시 문구/사진을 유지한 채 장소를 재확인한다.

동일 provider ID는 한 target이며 사용자의 분류는 favorite에 있다. 코스는 공유 ID 또는 새로운 경로 생성 의도로 명확히 구분한다. 코스 이름·경로를 일반 참여자가 수정하는 API/버튼은 없다.

## 산책코스 작성

지도 중심 십자선 위치에서 **점 추가 → 마지막 점 취소 → 완료**를 사용한다. 이름 1~50자, 서로 다른 좌표 최소2개·최대200개. 저장 좌표 순서는 [lng,lat]. 더블클릭/우클릭 완료는 모바일 필수 조작으로 쓰지 않는다.

작성한 선의 길이만 참고 거리로 표시하고 공식 보행 경로·예상 시간이라고 표현하지 않는다. 브라우저 SDK 길이는 표시용이고 서버가 좌표로 다시 계산한다. 경로 모양의 유사성으로 다른 코스를 자동 합치지 않는다. 부스는 시작점만 pin으로 표시하고 선택한 코스 하나의 전체 선만 펼친다. 관리자도 같은 편집기를 사용한다.

## 입력·실패

문구는 trim 후 grapheme 1~100, 닉네임 1~20, 팀/분류는 선택 목록의 ID다. 종류가 다른 분류 변경은 막는다. 선택 중단은 새 선택에서만 제외하고 기존 목록/조회는 유지한다.

제출 실패는 문구·File·ready asset ID·requestKey를 유지한다. 사진별 준비/업로드/처리/실패 상태를 표시한다. 한 장 실패를 조용히 제외해 성공시키지 않는다. 내부 이탈은 확인하며 동의하면 초안 폐기; 새로고침·브라우저 종료 복구는 제공하지 않는 기본안이다. beforeunload만으로 모바일 이탈을 완전히 막을 수 있다고 가정하지 않는다.

전체 삭제 확인에는 target 이름/건수/버전을 표시한다. 충돌 시 최신 영향 범위를 보여 다시 확인하며, 사용자가 취소하면 서버 쓰기는 없다. 닉네임·팀 수정은 모든 등록에 현재 값으로 반영된다.

## 성능·접근성

지도와 첫 공개 데이터는 병렬 로드한다. 관리자·코스 편집기·사진 전처리는 route 단위 lazy load. 첫 화면에 모든 상세·사진·코스 좌표를 받지 않는다. 핀은 가능한 한 기존 지도 객체를 재사용해 전체 지도 재생성을 피한다.

애니메이션은 등록 피드백·핀·순위 변경에만 짧게 사용하고 완료할 때까지 입력을 잠그지 않는다. CSS와 지도 pan 옵션 모두 reduced-motion을 반영한다. 그라데이션 없음. Dialog focus 복원, 하단 safe area, 키보드에 가려지는 입력, 친근한 오류 문구를 확인한다.

Figma 스펙이 생기기 전에는 DOM·computed style·콘솔·네트워크로 동작을 검증한다. 화면이 비슷해 보인다는 이유로 일치 판정하지 않는다. 이 문서는 화면의 기술 흐름이며 완성된 시각 디자인은 아니다.
