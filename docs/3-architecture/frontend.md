## URL과 상태

| 경로 | 표시/상태 |
| --- | --- |
| `/` | 삼성역 중심 전체 지도·플로팅 상위5개 랭킹·등록 버튼 |
| `/rankings?rankingTab=&team=&category=` | 5개 탭·커스텀 내부 팀/분류 필터·탭과 지도 동일 조건·공동 순위·20건씩 무한 스크롤 |
| `/targets/:id?team=&category=` | 지도 위 필터 없는 전체 상세 시트/패널, 본인 등록 관리 |
| `/register` | 지도 위 장소 등록·경로 등록 선택 패널; target/favorite 지정 시 기존 등록·수정으로 직접 진입 |
| `/register/places`, `/courses/new` | 전체 지도 검색·결과핀 선택/코스 준비·등록 패널·진입 시 참여 정보 모달 |
| `/me/favorites`, `/me/profile` | 공통 카드 스타일의 독립 페이지: 본인 목록/닉네임 수정, 팀은 운영자 정정 안내 |
| `/booth` | 전체 지도·전체 팀 카테고리별 플로팅 랭킹·핀 필터·순서 알림 |
| `/admin/login`, `/admin/*` | 인증·목록 관리·정정·삭제 영향 확인 |

React Router browser history를 쓰고 Vercel의 `vercel.json`에 SPA rewrite를 설정한다. 구현 시 `/`, `/rankings`, `/targets/:id`, `/register`, `/register/places`, `/courses/new`, `/me/:path*`, `/booth`, `/admin/:path*`만 `/index.html`로 연결한다. 직접 상세 링크/새로고침도 index.html을 받아야 하며 JS/CSS/없는 asset까지 HTML로 바꾸지 않는다. API는 Supabase URL로 명시적으로 호출한다.

서버 데이터는 Query, 필터는 URL, 작성 초안은 작성 화면 상태, 자격만 localStorage다. 서버 count를 optimistic +1로 확정하지 않는다. 성공 응답과 최신 상세를 확인한 뒤 완료 표시한다. 상세는 항상 전체 등록을 표시하며 원래 탐색 필터는 복귀용으로 보존한다.

## 지도·실제 장소

카카오 Web SDK는 singleton loader로 한 번 로드한다. 검색은 Edge Local REST를 사용하고 앱이 그린 검색 결과 marker를 선택한다. 지도 바탕의 모든 POI 클릭에서 ID를 얻을 수 있다고 가정하지 않는다. 임의 핀/이름으로 PLACE를 등록하는 입력은 없다.

검색은 입력 후 300ms debounce, 요청 취소, 서버 페이지 크기 15, 결과 없을 때 재검색. 삼성역 기준 좌표 [127.0632,37.5088]와 카카오 `sort=distance`로 모든 페이지를 가까운 순으로 조회한다. 지도 이동·현재 위치는 정렬 기준을 바꾸지 않으며 다른 지역을 차단하지 않는다. 선택된 서버 결과를 서명 토큰으로 보관하고 작성 폼에는 사람이 읽을 이름·주소를 보여준다. 30분 만료 시 문구/사진을 유지한 채 장소를 재확인한다.

동일 provider ID는 한 target이며 사용자의 분류는 favorite에 있다. 코스는 공유 ID 또는 새로운 경로 생성 의도로 명확히 구분한다. 코스 이름·경로를 일반 참여자가 수정하는 API/버튼은 없다.

## 산책코스 작성

지도 중심 십자선 위치에서 **점 추가 → 마지막 점 취소 → 완료**를 사용한다. 이름 1~50자, 서로 다른 좌표 최소2개·최대200개. 저장 좌표 순서는 [lng,lat]. 더블클릭/우클릭 완료는 모바일 필수 조작으로 쓰지 않는다.

작성한 선의 길이만 참고 거리로 표시하고 공식 보행 경로·예상 시간이라고 표현하지 않는다. 브라우저 SDK 길이는 표시용이고 서버가 좌표로 다시 계산한다. 경로 모양의 유사성으로 다른 코스를 자동 합치지 않는다. 부스는 시작점만 pin으로 표시하고 선택한 코스 하나의 전체 선만 펼친다. 관리자도 같은 편집기를 사용한다.

## 입력·실패

문구는 선택 입력이며 trim 후 grapheme 0~100, 닉네임 1~20, 팀/분류는 선택 목록의 ID다. 종류가 다른 분류 변경은 막는다. 선택 중단은 새 선택에서만 제외하고 기존 목록/조회는 유지한다.

제출 실패는 문구·File·ready asset ID·requestKey를 유지한다. 사진별 준비/업로드/처리/실패 상태를 표시한다. 한 장 실패를 조용히 제외해 성공시키지 않는다. 내부 이탈은 확인하며 동의하면 초안 폐기; 새로고침·브라우저 종료 복구는 제공하지 않는다. beforeunload만으로 모바일 이탈을 완전히 막을 수 있다고 가정하지 않는다.

전체 삭제 확인에는 target 이름/건수/버전을 표시한다. 충돌 시 최신 영향 범위를 보여 다시 확인하며, 사용자가 취소하면 서버 쓰기는 없다. 닉네임·팀 수정은 모든 등록에 현재 값으로 반영된다.

## 성능·접근성

지도와 첫 공개 데이터는 병렬 로드한다. 관리자·코스 편집기·사진 전처리는 route 단위 lazy load. 첫 화면에 모든 상세·사진·코스 좌표를 받지 않는다. 핀은 가능한 한 기존 지도 객체를 재사용해 전체 지도 재생성을 피한다.

애니메이션은 등록 피드백·핀·순위 변경에만 짧게 사용하고 완료할 때까지 입력을 잠그지 않는다. CSS와 지도 pan 옵션 모두 reduced-motion을 반영한다. 그라데이션 없음. Dialog focus 복원, 하단 safe area, 키보드에 가려지는 입력, 친근한 오류 문구를 확인한다.

Figma 스펙이 생기기 전에는 DOM·computed style·콘솔·네트워크로 동작을 검증한다. 화면이 비슷해 보인다는 이유로 일치 판정하지 않는다. 이 문서는 화면의 기술 흐름이며 완성된 시각 디자인은 아니다.

## 지도 중심 UI 개편 (2026-10-13 이력)

아래는 1차 개편 합의 이력이며 현재 화면 정책은 하단 2차 UI 피드백을 우선한다.

- `/`·`/rankings`·`/targets/:id`는 공통 지도 레이아웃에서 패널만 전환한다. 직접 링크와 새로고침을 지원하며 URL 필터·지도 위치·뒤로가기/닫기 복귀를 유지한다. 내 최애·내 정보는 독립 페이지다.
- 지도는100dvh, PC 상세는 왼쪽 플로팅 패널, 모바일은 요약/중간/확장 바텀시트다. 손잡이 드래그와 키보드 가능한 높이 버튼을 제공한다. 비모달 시트 바깥 지도는 조작 가능하며, 목록 스크롤과 드래그를 분리한다.
- 메인 상위5개는 첫 랭킹 페이지에서 조회하며 전체 랭킹 페이지 이동과 독립이다. 모바일은 가로 스크롤, PC는 카드. 서버 공동순위와 ID 내부 순서를 유지한다.
- 상세는 기존 최애 데이터를 댓글처럼 표시한다. 다음20건을 누적하며 필터/대상/revision 변경 시 목록을 초기화한다. 새 댓글/답글/좋아요 기능은 없다.
- 검색 목록과 결과핀으로 실제 장소를 선택하면 이름·주소와 입력폼을 연다. 등록/수정/산책코스도 전체 지도와 패널을 사용한다. 코스 편집기의 관리자 사용은 기존 인라인 지도를 유지한다.
- 지도 객체는 패널 전환에 재생성하지 않는다. resize시 relayout, 선택핀 위치는 실제 패널 점유 영역 밖으로 조정한다. 키보드·safe area·reduced-motion·포커스 복원을 반영한다.
- 흰 카드·초록 포인트·얇은 테두리·그림자·입력·버튼을 개인 페이지와 공유한다. 팀 직접 수정은 계속 운영자만 가능하다.
- 사용자가 제공한 실제 팀 `백엔드개발팀`·`프론트엔드개발팀`을 추가한다. 기존 동일 정규화 이름은 변경하지 않으며 실제 삽입 시 revision을 갱신한다.
- 배포 범위: 검증 후 feature→develop PR, release→main/develop PR, 개인 Vercel 최종커밋 READY 및 실제 운영 응답 확인.

## UI 피드백 2차 (2026-10-14)

- IT센터 브랜드 플로팅 카드는 모든 지도 화면에서 제거한다. PC 개인 메뉴는 유지하고 모바일 개인 메뉴는 메인·상세에서 오른쪽 트리거/가장자리 드래그로 여는 사이드 패널에 배치한다. 등록 종류 선택·장소 검색·경로 지정·등록/수정 화면에서는 모바일 메뉴 전체를 렌더링하지 않는다. 패널 닫기·배경/ESC·포커스 관리와 키보드 대체 버튼을 제공한다.
- 기본 필터는 전체 팀·전체 카테고리. 모바일 메인 최상단에 API 최신 상위5개의 순위·이름·건수를4초마다 세로 전환하는 티커를 배치한다. hover/focus/숨김 중 정지, 사용자 정지 버튼과 reduced-motion을 지원한다. 실제 서버 rank와 동점 규칙은 유지한다.
- 장소/코스 상세의 팀·분류 필터와 조건별 보기 전환은 제거하고 지도·상세 모두 전체 기준으로 조회한다. 메인의 탐색 필터는 돌아갈 URL 상태로만 유지한다. 모바일 상세는 초기70% 높이로 열고 요약/확장으로 조절한다.
- 내 위치 버튼은 클릭 때 Geolocation 요청→파란점 표시→해당 좌표로 지도 이동. 위치는 서버나 저장소로 보내지 않는다. 권한거절/미지원/시간초과는 toast로 설명하며 기존 지도를 유지한다.
- 사진 selected/preparing/uploading/processing 단계에는 원본/처리본 미리보기 위 dim과 indeterminate 원형 로딩/진행바·상태문구를 표시한다. ready에서 dim 제거, 실패 시 재시도/제거를 유지한다.
- 등록 오류는 toast로 새 오류가 보이게 알리고 입력·사진·불확실 제출 상태는 유지한다. 일반 장소 다시 선택 버튼은 제거한다. 삭제된 대상 등 재선택이 필요한 오류는 명시 취소/새등록으로 복구하며 재선택 시 작성 중 초안은 이탈확인 규칙을 따른다.
- dialog는 CSS preflight와 무관하게 viewport 정중앙에 표시하고 max-height/내부스크롤/safe-area를 적용한다.
- 브라우저 연결과 로그인은 이번 개선에서 제외한다. 브라우저별 localStorage 자격을 유지하고 브라우저 변경 시 별개 참여 정보라는 안내를 표시한다. public ID/닉네임/팀은 인증 수단이 아니다.

### 2차 추가 레이아웃 피드백

- PC 필터는 랭킹 패널과 같은380px/동일폭2열로 제한하고 라벨은 줄바꿈하지 않는다. select는 목록의 가장 긴 이름 때문에 카드 폭을 늘리지 않는다.
- 개인 화면 명칭은 `내 장소/코스`, 프로필 진입은 `내 정보`로 통일한다. 메뉴/영문 장식 문구는 번역 제외 표시로 중복 표시를 방지한다.
- 개인 목록은 minmax(0,1fr) 열과 긴 제목 anywhere 줄바꿈으로 모바일 가로넘침을 막는다.
- 지도 핀 라벨의 기본/선택/hover 그림자와 filter를 제거한다. 키보드 포커스 outline은 유지한다.

- PC 필터와 개인 메뉴의 플로팅 높이는44px로 통일한다. 장소 연속 선택은 기존 패널 DOM을 유지하면서 내용을 교체하고 스크롤/시트높이를 초기화한다. 상세/랭킹 X는 이전 장소가 아닌 메인으로 즉시 복귀하며 탐색 필터만 유지하고 랭킹페이지는 초기화한다. 상세간 선택은 history replace로 누적하지 않는다.

- PC 메인 필터와 개인 메뉴는 상단24px 기준선에 정렬한다. 랭킹/상세 패널은 필터 하단과16px 간격(상단84px)을 유지한다. 모바일 티커/필터 배치는 변경하지 않는다.

## 등록 UX 추가 개선 (2026-10-14)

- 일반 최애 등록 진입은 지도 위 선택 패널에서 `장소 등록` → `/register/places`, `경로 등록` → `/courses/new`로 나뉜다. 기존 대상 추가·내 등록 수정은 선택을 건너뛴다.
- 선택에서 전달된 `return` 필터는 준비/작성 및 성공 후 상세까지 보존한다. 준비 화면의 상호 전환 버튼을 제거하고 뒤로가기로 선택 패널에 복귀한다. 작성 중에는 기존 초안 이탈확인을 적용한다.

- 검색 결과 목록 또는 결과핀으로 장소를 선택하면 해당 장소를 기준으로 카카오 level3까지 확대한다. 이미 level1~2이면 유지하고, 패널이 가리지 않는 지도 영역 중심으로 보정한다. 선택 이후 사용자의 수동 줌은 재렌더링으로 초기화하지 않는다.

## 모바일 검색 배치·검색 복귀 (2026-10-14)

- 모바일 등록 화면의 검색바는 top16px, 확대/축소/내위치 버튼은 top74px로 올린다. 검색바가 없는 등록 종류/코스 화면의 지도 버튼은 top16px에 배치한다. 메인 티커/필터와 PC 위치는 유지한다.
- 검색 결과 선택은 같은 `/register/places` 경로에 선택 장소를 history state로 push한다. 브라우저 뒤로가기와 선택 화면 X는 기존 검색어·페이지·목록 스크롤·결과핀을 보여준다. 작성 입력이 없는 선택은 즉시 복귀하고, 문구·사진 등 초안 변경 후에는 폐기 확인을 거쳐 복귀한다. 취소하면 선택 장소와 초안을 유지한다. 새로고침 후 검색 초안 복구는 제공하지 않는다.

- 등록/수정 하단의 `작성 취소` 링크는 제거한다. 신규 등록은 제출 버튼만, 수정은 저장·내 등록 삭제 버튼을 유지한다. 종료는 패널 X/뒤로가기로 제공하며 기존 초안 폐기 확인을 유지한다.

- 탐색·랭킹·상세 배경·부스 지도에만 활성화한다. 장소 검색 결과와 코스 편집은 기존 개별 핀 동작을 유지한다. 코스는 시작점 좌표로 묶고 선택한 코스의 경로만 그린다.

- 현재 지도 투영 좌표와 DOM에서 측정한 원본 라벨 사각형의 교집합 면적을 작은 쪽 라벨 면적으로 나눠50% 이상일 때만 묶는다. 대상ID 순서로 처리하며 묶음의 모든 기존 구성원과50% 조건을 만족할 때만 추가한다. 원본 좌표의 평균에 묶음을 둔다. 첫 묶음에는8px 여백이나 원본의 약한 연쇄 겹침을 사용하지 않는다. 이어 최종 표시 라벨(묶음-묶음 및 묶음-개별)의 실제 사각형 면적도50% 이상 겹치면 병합한다. 대상ID 기준 순서로 한 쌍씩 병합하고 라벨 크기·원본 핀 수로 가중한 평균 위치를 재계산해 다시 검사한다. 매번 그룹 수가 줄어 유한하게 종료하며 최종 라벨에50% 이상 겹침이 없을 때 끝난다. 상세 선택ID는 이 단계에서도 제외한다. 매번 원본 핀부터 계산하므로 확대 후 최종 라벨도50% 미만으로 벌어지면 일부 겹침이 남아도 개별 표시로 복원되며 동일 좌표는 계속 묶인다.
- 최초 표시·지도 idle·화면/패널 크기·폰트 로드·핀 데이터 변경 시 계산한다. 지도 객체는 유지하고 그룹 ID 집합을 키로 오버레이를 재사용한다. 등록 수 합계가 아닌 대상 개수를 표시하며 상세 선택 대상은 클러스터에서 제외해 별도 이름 라벨로 강조한다. 해제 시 오버레이·측정 DOM·관찰자·이벤트를 정리한다.
- 묶음 클릭은 자동 확대 없이 비모달 목록 팝업 하나를 연다. 등록 수 내림차순→한국어 이름→대상 ID 순으로 이름·종류·조건별 최애 수를 표시한다. PC/모바일 최대280px 폭·목록 최대300px 스크롤이며 지도 가장자리12px와 기존 패널·컨트롤 영역을 피한다. 여유 영역이 작으면 팝업 높이를 줄인다.
- 닫기/Escape는 트리거에 포커스를 돌린다. 지도 빈 곳 클릭·이동/확대 시작·조회 조건/선택 대상 변경은 닫고, 같은 묶음의 데이터 갱신은 최신 이름·횟수로 교체한다. 묶음이 해제되면 닫는다. 목록 클릭/스크롤은 지도 조작으로 전파하지 않는다.
- 항목 선택 시 팝업을 닫고 기존 onSelect 경로를 사용한다. 선택 ID는 클러스터 계산에서 제외하고 단독 핀/라벨은 화면좌표 역변환 없이 원래 lng/lat를 그대로 SDK LatLng에 전달한다. 선택 마커·라벨은zIndex5로 나머지1보다 앞에 표시한다. 상세 응답이 전달한 저장 좌표·이름·코스 시작점/경로를 사용하고 패널 밖 보이는 지도 영역으로 위치를 보정한다. 나머지 항목은50% 기준 묶음을 유지하며 상세 종료로 선택ID가 해제되면 다시 묶음에 포함한다. 탐색/랭킹은 쿼리·history 교체 규칙을 유지해 상세로 이동하고 부스는 내부 상세 패널을 연다. 등록0건 직접 상세는 기존 빈 상태를 유지한다.


## 장소·산책코스 상세 지도 자동 확대 (2026-10-15)
