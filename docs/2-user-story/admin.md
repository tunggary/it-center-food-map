# 관리자 사용자 스토리와 화면 흐름

[전체 목차](../2-user-story.md) · [QA 상세](qa/admin.md) · [확정 결정](decisions.md)

이 문서의 화면은 기능 단위다. 별도 페이지·모달·패널 중 어떤 형태로 구현할지는 후속 화면 설계에서 정한다. 아래 분기 표는 요약이며, 준비 상태·실행 절차·기대 결과의 기준은 연결된 QA 항목이다.

## 사용자 스토리

### US-A-01

- **스토리:** 나는 행사에 맞는 팀과 카테고리를 준비하고 운영하고 싶다.
- **시작 조건:** 관리 권한 확보
- **흐름:** 추가·이름 변경·신규 선택 중단 → 참여 화면 확인
- **완료 조건:** 신규 선택 목록이 갱신되고 기존 데이터는 유지된다.
- **근거:** [PRD](../1-prd.md) §4, 7.

### US-A-02

- **스토리:** 나는 팀 오입력과 공유 코스의 잘못된 정보를 정정하고 싶다.
- **시작 조건:** 관리 권한과 정정 대상 확인
- **흐름:** 팀 또는 코스 정정 → 저장 → 참여·집계 확인
- **완료 조건:** 팀별 집계와 기존 표시가 변경 사항을 반영한다.
- **근거:** [PRD](../1-prd.md) §2, 4, 7.

### US-A-03

- **스토리:** 나는 잘못된 등록을 필요한 범위만큼 삭제하고 싶다.
- **시작 조건:** 관리 권한과 삭제 대상 확인
- **흐름:** 개별 또는 전체 대상 → 영향 확인 → 실행·취소
- **완료 조건:** 삭제 대상과 집계가 일치하고 취소 시 변화가 없다.
- **근거:** [PRD](../1-prd.md) §5, 7.

## 흐름도

그림은 주요 경로를 나타낸다. 연결된 분기 표와 QA에 입력 경계·오류·확정 정책이 더 상세히 기록돼 있다.

### F-A-01 목록 관리·정정

SC-A-01~02; BR-A-01 및 BR-A-02; 인증 세부는 DEC-09

```mermaid
flowchart TD
    access["관리 권한 확인"] --> target{"작업 선택"}
    target -->|"팀과 카테고리"| lists{"목록 작업"}
    lists -->|"추가"| add["팀 또는 유형별 카테고리 추가"]
    lists -->|"이름 변경"| rename["소속과 집계를 유지해 이름 변경"]
    lists -->|"신규 선택 중단"| stop["신규 선택 제외와 기존 조회 유지"]
    target -->|"참여자 팀"| team["팀 오입력 정정"]
    team --> recount["기존 표시와 팀별 집계 갱신"]
    target -->|"공유 코스"| course["이름과 경로 정정"]
    course --> keep["기존 등록을 유지해 정보 갱신"]
    target -->|"취소"| cancel["변경 없이 작업 종료"]
    add --> check["작업 결과 확인"]
    rename --> check
    stop --> check
    recount --> check
    keep --> check
    check -->|"실패"| failure["실패와 재시도 정책 DEC-06"]
```

### F-A-02 개별·전체 삭제

SC-A-03; BR-A-03-01~04; 동시 변경 DEC-06

```mermaid
flowchart TD
    target["삭제 대상 선택"] --> scope{"삭제 범위"}
    scope -->|"개별 등록"| single["특정 참여자의 등록 삭제"]
    single --> remain{"남은 등록 존재"}
    remain -->|"예"| keep["항목 유지와 집계 감소"]
    remain -->|"아니오"| remove["지도와 랭킹 제외"]
    scope -->|"장소 또는 코스 전체"| inspect["대상과 영향 등록 수 확인"]
    inspect --> decide{"전체 삭제 실행"}
    decide -->|"취소"| unchanged["모든 데이터 유지"]
    decide -->|"실행"| result{"삭제 결과"}
    result -->|"성공"| allRemoved["연결된 모든 등록과 공개 내용 제거"]
    allRemoved --> remove
    result -->|"실패 또는 동시 변경"| pending["정책 확인 DEC-06"]
```


## 확정된 관리 정책

사전 관리자 계정+서버 허용 목록을 사용하며, 만료/권한 상실 시 작업을 거절하고 초안을 유지한다. 목록명1~30자·유형별 중복 금지, 선택 재개 허용·카테고리 유형 고정이다. 중단된 팀의 기존 참여는 허용한다. 전체 삭제 영향이 달라졌으면 재확인하며 관리자 삭제 후 새 등록을 허용한다.
