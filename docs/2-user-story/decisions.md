# 결정 필요 사항

[전체 목차](../2-user-story.md)

여기에 있는 항목은 요구사항에 몰래 추가한 정책이 아니다. 사용자 흐름을 구체화하면서 드러난 미정 사항이며, 관련 QA는 기대 결과 확정 전까지 판정 보류한다. 기능 전체를 새로 승인받는 절차가 아니라 해당 분기의 동작을 정하기 위한 목록이다.

## DEC-01

- **산책 경로 작성·정정:** 지도 서비스에서 가능한 입력 방법, 경유지·보행 경로 표현, 이름·경로 검증 방법, 제공되지 않는 거리·시간 표시.
- **확정된 경계:** 이름·경로 필수, 기존 코스 재등록은 합산, 유사 신규 코스는 별개, 공유 코스 정정은 관리자만 가능.
- **확정 시점:** 지도 기능 조사와 화면 설계 시. 참여자·관리자 경로 작성 QA 전 필요.

## DEC-02

- **행사 조건:** 일정·운영 시간·전체 인원·팀 수·실제 팀 목록·네트워크·부스 화면 준비·사전 참여 여부.
- **확정된 경계:** 동시 접속 목표 100명, 행사 종료 후에도 참여, 현장 재미를 피드백으로 확인.
- **확정 시점:** 첫 버전 범위와 검증 계획 확정 전.

## DEC-03

- **랭킹·목록 표시:** 모바일 기본 랭킹 조건, 한 줄 랭킹의 항목 선택·전환 방식, 최대 노출 건수, 동점 내부 순서, 상세 문구 정렬·더 보기, 부스의 카테고리별 랭킹 배치와 핀 필터 연동 여부.
- **확정된 경계:** 누적 등록 횟수, 공동 순위, 팀·카테고리 조합. 부스 핀 필터를 바꾼다고 다른 카테고리 랭킹까지 사라진다고 가정하지 않는다.
- **확정 시점:** 화면 설계 시. 순위 계산 QA와 표현 QA를 분리한다.

## DEC-04

- **입력 세부 규칙:** 공백만 있는 문구, 줄바꿈·이모지의 문자 수, 닉네임 길이·공백 처리, 사진 형식·용량·전송 실패 시 개별 상태.
- **확정된 경계:** 문구 1~100자, 사진 최대 3장 선택, 닉네임 중복 허용. QA의 ASCII 경계값은 현재 기준으로 바로 검증 가능하다.
- **확정 시점:** 등록 화면 설계·검증 계획 확정 전. 임의 제한을 PRD에 추가하지 않는다.

## DEC-05

- **이탈과 초기 실패:** 작성 중 취소·뒤로가기·새로고침 후 보존, 이탈 확인, 취소한 첫 참여 정보 유지, 목록 로딩 자체가 실패한 경우, 첫 접속부터 오프라인인 경우의 안내·재시도.
- **확정된 경계:** 현재 작성 화면에서 통신 실패하면 문구·사진을 유지한다. 기존 지도·랭킹이 있을 때 연결 중단은 마지막 결과를 유지한다.
- **확정 시점:** 화면별 빈 상태·실패·이탈 설계 시.

## DEC-06

- **관리·수정 실패와 동시 변경:** 수정·삭제 실패 후 상태·재시도, 삭제 확인 이후 영향 등록 수가 달라진 경우, 작성 중 대상이 삭제된 경우, 열어 둔 상세에서 대상이 사라진 경우.
- **확정된 경계:** 전체 삭제 전 대상·영향 개수를 확인하며 취소는 데이터를 바꾸지 않는다. 성공하지 않은 작업을 성공으로 안내하지 않는다.
- **확정 시점:** 변경·삭제 흐름 상세 설계 시. API·동시성 구현 방법은 이후 기술 설계에서 다룬다.

## DEC-07

- **삭제 후 재참여:** 개인 삭제의 확인·취소 UX, 본인 삭제 후 같은 항목 재등록, 관리자 삭제 후 재등록, 전체 삭제된 코스의 재생성·접근 안내.
- **확정된 경계:** 삭제하면 공개 문구·사진·집계에서 제외하고 마지막 등록이 없어지면 공동 지도에서 제외한다. 숨김·복구 기능은 없다.
- **확정 시점:** 등록·삭제 상세 설계 시. 삭제 결과의 공개 제외와 저장소의 보관·삭제 정책은 구분한다.

## DEC-08

- **팀·카테고리 관리:** 목록 이름 검증·중복, 선택 재개, 카테고리 유형 변경 가능 여부, 중단된 팀의 기존 참여자가 추가 등록할 수 있는지, 작성 중 카테고리 선택이 중단됐을 때 처리.
- **확정된 경계:** 신규 선택 중단 후 기존 등록과 필터·랭킹은 유지한다. 참여자는 팀을 직접 변경할 수 없다.
- **확정 시점:** 관리 화면과 참여 화면 연결 설계 시.

## DEC-09

- **관리자 접근:** 관리 기능의 진입·인증 실패·세션 만료·권한 상실 시 사용자 흐름.
- **확정된 경계:** 일반 참여자의 무로그인 요구와 관리자 권한은 구분한다. 일반 참여자가 팀 정정·전체 삭제 등을 실행할 수 있다는 뜻이 아니다.
- **확정 시점:** 관리자 사용자 흐름 확정 및 후속 인증 설계 시. 인증 기술은 이 문서에서 선택하지 않는다.

## DEC-10

- **부스 알림:** 한 건 노출 시간, 대기 한계, 재접속·새로고침 이후 지난 알림 재생 여부, 대기 중 닉네임 변경·등록 삭제 반영, 동시에 발생한 알림의 순서 판정.
- **확정된 경계:** 모든 최애 등록을 순서대로 알린다. 알림 대기 지연은 허용하지만 지도·랭킹 반영 5초 목표와 분리한다. 수정·삭제를 새로운 등록 알림으로 만들지 않는다.
- **확정 시점:** 부스 화면 상세 설계 시.

## DEC-11

- **참여 정보 상실:** 브라우저 기록 삭제나 기기 변경 이후 소유권·정정 요청 처리, 운영자가 동명 참여자의 요청을 구분하는 방법.
- **확정된 경계:** 닉네임·팀이 같다고 같은 사람으로 합치지 않는다. 다른 기기의 재참여를 엄격히 막지 않는다.
- **확정 시점:** 내 최애 관리 및 현장 운영 절차 확정 시. 자동 계정 복구나 실명 인증을 임의 도입하지 않는다.

## DEC-12

- **측정 조건:** 정상 네트워크 수치, 캐시·지도 범위·데이터 양, 동시 접속자의 행동 비율, 반복 측정 횟수·합격 통계, 첫 사용자 테스트 인원·완료 비율.
- **확정된 경계:** 100명 동시 접속, 첫 지도·랭킹 3초, 사진 없는 등록 2초, 타 화면 반영 5초, 첫 장소 등록 2분. 수치는 임의 완화하지 않는다.
- **확정 시점:** QA 실행 계획 확정 전. 환경 미정이어도 관찰값은 기록할 수 있으나 최종 합격 근거로 취급하지 않는다.

## 아키텍처 설계와의 연결 (2026-10-13)

[아키텍처의 DEC별 구현 기본안](../3-architecture/policies.md#8-dec별-구현-기본안)에 DEC-01~12 전부의 제안 또는 필요한 운영 사실을 연결했다. 기술 구현자가 기준 없이 선택하지 않도록 기본안을 정한 것이며, 사용자 합의나 제품 QA 통과를 뜻하지 않는다.

- DEC-01: [ADR-0004](../3-architecture/adr/0004-kakao-map-and-courses.md)의 지도·직접 경로 작성.
- DEC-04·05: [ADR-0006](../3-architecture/adr/0006-photo-lifecycle.md)의 사진 수명주기와 아키텍처의 입력/초안 정책.
- DEC-06·07·08: [ADR-0002](../3-architecture/adr/0002-domain-and-transactions.md)의 동시성·삭제·정정 모델.
- DEC-09·11: [ADR-0003](../3-architecture/adr/0003-identity-and-authorization.md)의 브라우저 소유권·관리자 인증.
- DEC-10: [ADR-0005](../3-architecture/adr/0005-state-sync-and-announcements.md)의 상태 동기화·알림 재생.
- DEC-02·12: [드라이버의 가정·검증 계획](../3-architecture/drivers.md)의 운영 조건·측정 제안. DEC-03은 아키텍처의 화면 기본안.

기존 분기와 QA의 판정 보류 상태는 유지한다. 제품 정책을 채택할 때 PRD → 스토리·분기 → QA 기대 결과를 함께 갱신한다.

무료 조건을 반영한 세부 설계는 [설계 폴더](../3-architecture/README.md)에 모았다. 비용 조건만 PRD §10에 합의 내용으로 추가했다. 휴면 수동 재개·사진 크기·알림 재생 등 제품/운영 기본안은 가정으로 구분하고 원본 QA 상태를 유지한다. 기존 Node/Vercel 기반 API·cookie·사진 처리 방식은 현재 구현 기준이 아니다.
