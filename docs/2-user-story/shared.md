# 공통 품질·운영 사용자 스토리와 화면 흐름

[전체 목차](../2-user-story.md) · [QA 상세](qa/shared.md) · [확정 결정](decisions.md)

이 문서의 화면은 기능 단위다. 별도 페이지·모달·패널 중 어떤 형태로 구현할지는 후속 화면 설계에서 정한다. 아래 분기 표는 요약이며, 준비 상태·실행 절차·기대 결과의 기준은 연결된 QA 항목이다.

## 사용자 스토리

### US-N-01

- **스토리:** 나는 휴대폰이나 부스에서 빠르고 읽기 쉬운 서비스를 사용하고 싶다.
- **시작 조건:** 지원 기기와 합의한 부하 조건
- **흐름:** 핵심 흐름 수행·측정
- **완료 조건:** 성능 목표·친근한 문구·동작 줄이기·사용성 목표를 확인한다.
- **근거:** [PRD](../1-prd.md) §8.

### US-N-02

- **스토리:** 나는 연결이 끊겨도 상태를 이해하고 작성한 내용을 다시 제출하고 싶다.
- **시작 조건:** 조회 또는 등록 작성 중
- **흐름:** 연결 중단 → 안내 → 복구·재시도
- **완료 조건:** 오래된 표시를 최신이라고 오인하지 않고 결과를 중복 생성하지 않는다.
- **근거:** [PRD](../1-prd.md) §8.

### US-N-03

- **스토리:** 나는 행사 후에도 참여하고 현장의 불편·재미를 운영자에게 전달하고 싶다.
- **시작 조건:** 행사 운영 및 종료 후
- **흐름:** 참여·현장 피드백 전달
- **완료 조건:** 별도 앱 내 의견 기능 없이 피드백을 수집하고 이후 개선에 연결한다.
- **근거:** [PRD](../1-prd.md) §1, 9.

## 측정·기록 원칙

- 최초 표시: 주소 접속을 시작한 시점부터 지도와 랭킹을 모두 확인·조작할 수 있는 시점까지.
- 등록 완료: 사진 없는 유효 입력에서 제출한 시점부터 완료 안내와 해당 상세의 등록 결과를 확인 가능한 시점까지.
- 다른 화면 반영: 등록 성공 확인부터 다른 참여자와 부스 각각의 지도·랭킹 갱신까지. 알림 표시 대기 시간은 별도 기록.
- 첫 참여: 처음 쓰는 사람이 QR을 여는 시점부터 최초 장소 등록 결과를 확인할 때까지. 사진·산책 경로 작성은 제외.
- 측정값은 요구 수치를 바꾸지 않는다. 표본·네트워크·캐시·합격 비율은 확정된 DEC-12를 사용해 전체 통과 여부를 판정한다.
- 사진 업로드·외부 지도 지연은 숨기지 않고 별도 관측한다. 외부 지연이 있다는 이유로 실제 첫 표시 측정값을 임의 차감하지 않는다.


## 확정된 운영·판정 기준

제품 배포 즉시 사전 참여를 받고 행사 후에도 등록을 유지한다. 무료 DB 휴면은 운영자 수동 재개를 허용한다. 첫 표시/무사진 완료는 각각100표본의95% 이상에서3초/2초, 타 화면5초는 모든 정상 연결표본, 첫 사용자5명 모두2분이다. 수동 백업은 행사 전후·DB 변경 전·변경이 있었던 주에 수행한다. 실제 행사 정보는 출시 입력이며 판정 규칙의 미정 항목이 아니다.
