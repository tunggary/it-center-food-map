# 사용자 스토리·화면 흐름·QA

[PRD](1-prd.md) · [진행 현황](README.md)

이 문서는 PRD를 역할별 사용자 행동, 화면 분기, 재현 가능한 QA로 연결한다. 기술·API·데이터 구조와 첫 버전 범위를 정하는 문서는 아니다. 화면은 기능 단위이며 페이지·모달·패널 형태는 후속 설계에서 결정한다.

## 읽는 순서와 식별자

1. 관련 PRD 항목을 읽고 역할 문서의 사용자 스토리를 확인한다.
2. 해당 화면의 진입·표시·행동과 분기 표를 읽는다.
3. 분기 행에 연결된 QA의 준비 상태·절차·기대 결과를 따른다.
4. 확정된 결정 기록과 QA 기대 결과를 사용하고 임의로 합격 기준을 바꾸지 않는다.

| 식별자 | 의미 | 기준 위치 |
| --- | --- | --- |
| US-P/B/A/N | 참여자·부스·관리자·공통 사용자 스토리 | 역할 문서의 제목 |
| SC-P/B/A | 기능 단위 화면 | 역할 문서의 화면 표 |
| SC-N | 공통 검증 영역·상태. 별도 제품 화면을 의미하지 않음 | 공통 문서 |
| BR-역할-화면-번호 | 한 화면에서 발생하는 조건·행동 분기 | 역할 문서의 분기 표 |
| QA-역할-화면-번호 | 동일 번호의 분기를 검증하는 시나리오 | QA 문서의 제목 |
| F-역할-번호 | 여러 화면을 잇는 Mermaid 흐름도 | 역할 문서 |
| DEC-번호 | 동작·운영 조건의 결정 기록 | 결정 목록 |

분기 표는 탐색용 요약이다. 상세 기대 결과는 연결된 QA가 기준이고, 요구사항을 바꾸는 경우에는 PRD를 먼저 갱신한 뒤 스토리·분기·QA를 같이 고친다.

## 역할 경계와 공통 규칙

- 첫 방문·기존 참여는 참여자의 상태다. 로그인 역할을 추가하지 않는다.
- 닉네임·팀은 첫 등록의 문구·사진 작성 과정에서 함께 입력한다. 등록 성공 후 해당 장소·코스 상세로 이동한다.
- 같은 브라우저의 참여 정보로 자신의 등록을 관리한다. 다른 기기·기록 삭제 후 동일인 보장은 하지 않는다.
- 부스 관람과 필터 조작은 관리자 전체 삭제 권한을 의미하지 않는다. 관리자 스토리는 권한이 확보된 상태를 전제하며 사전 이메일/비밀번호 계정과 서버 허용 목록으로 인증한다.
- 관리자와 일반 참여자의 수정 가능 대상을 구분한다. 참여자는 공유 경로를 바꾸거나 남의 등록을 관리할 수 없다.
- 사진과 문구는 공개된다. QA 데이터는 실제 참여자의 개인정보·사진 대신 테스트용 자료를 사용한다.
- 현재 제외된 기능은 별도 추천·좋아요·댓글, 숨김·복구, 앱 내 의견 접수다. 일반적인 UI 패턴이라는 이유로 재도입하지 않는다.
- 추가 화면 이동·저장 정책 중 PRD에 없는 중요한 결정은 DEC로 분리한다. 친근한 문구 예시는 확정 카피가 아니다.

## QA 준비 데이터

### FIX-01: 집계·필터·수정 검증

아래는 QA 전용 가명과 논리적 항목이다. 실제 지도 검색이 필요한 실행에서는 동일 관계를 갖는 실제 검색 가능 장소에 연결해 실행 기록에 적는다. 각 QA 시작 전에 데이터를 이 상태로 복원하거나 독립된 자료를 준비한다.

| 참여자 | 팀 | 최애 대상 | 등록 카테고리 |
| --- | --- | --- | --- |
| U1 | A팀 | L1 | 카페 |
| U2 | A팀 | L1 | 카페 |
| U3 | B팀 | L1 | 카페 |
| U4 | A팀 | L1 | 맛집 |
| U5 | A팀 | L2 | 카페 |
| U6 | C팀 | L2 | 카페 |
| U7 | C팀 | L2 | 카페 |
| U8 | C팀 | L3 | 카페 |
| U9 | C팀 | L3 | 카페 |

- L1 전체는 4건, 카페는 3건, 맛집은 1건이다.
- 전체 팀·카페 순위: L1=3건·공동 1위, L2=3건·공동 1위, L3=2건·3위.
- A팀·카페: L1=2건, L2=1건. B팀·카페: L1=1건. B팀·맛집: 0건.
- 각 참여자는 문구를 구분되게 남긴다. 일부는 사진 0장, 일부는 사진 1~3장으로 준비한다.
- 산책코스 R1은 최초 작성자 U1과 기존 코스를 선택한 U2가 각각 등록한다. R2는 별도 코스로 준비한다.
- 모바일·부스·관리자 간 확인은 서로 다른 브라우저 컨텍스트를 사용한다. 닉네임만 바꿔 다른 참여자를 흉내 내지 않는다.

## QA 실행 원칙

- 초기 실행 결과는 **미실행**이다. 기대 결과 자체에 미정 항목이 있으면 **판정 보류**다. 둘 다 실제 테스트를 통과했다는 뜻이 아니다.
- 실행 후에는 환경·시간·실제 결과·근거와 함께 통과·실패·판정 보류를 기록한다. 일부 관찰 성공으로 전체 항목을 통과 처리하지 않는다.
- 기본 검증은 DOM·computed style·콘솔·네트워크와 다른 화면의 결과를 확인한다. 화면이 비슷해 보인다는 이유만으로 통과시키지 않는다.
- 정적 준비 페이지만 배포된 현재 상태에서는 제품 QA를 실행하지 않는다. 자동화할 회귀 항목은 구현 후 위험도에 맞춰 선정하며 모든 문서 항목을 그대로 자동화할 필요는 없다.
- 기능의 수행 결과와 완료 후 화면 이동을 함께 확인한다. 변경 요청 성공만으로 UI·집계 갱신까지 확인했다고 간주하지 않는다.
- 성능 목표는 공통 문서의 측정 구간을 사용한다. 확정된 DEC-12의 조건·통계를 충족하는 시험에서만 전체 합격을 선언한다.

실행 기록 양식은 각 QA 항목 아래에 추가한다. 반복 실행은 이전 기록을 지우지 않고 남긴다.

```text
실행일 / 실행자:
대상 변경 또는 빌드:
기기 / OS / 브라우저 버전 / 네트워크:
준비 데이터와 사전 조건:
실제 수행 단계:
실제 결과 / 측정값:
증거 링크 또는 로그 위치:
결과: 미실행 / 통과 / 실패 / 판정 보류
실패 이슈 또는 보류 DEC / 후속 작업:
```

## 친근한 문구 예시

| 상태 | 의미를 확인하기 위한 예시 |
| --- | --- |
| 첫 등록 정보 | 지도에 남길 닉네임과 팀을 알려주세요. |
| 문구 입력 | 이곳이 최애인 이유를 짧게 들려주세요! |
| 필터 결과 없음 | 아직 이 조건에 맞는 최애가 없어요. 다른 팀이나 카테고리도 둘러보세요. |
| 중복 등록 | 이미 내 최애에 담긴 곳이에요. 남긴 내용을 확인해 보세요. |
| 등록 완료 | 내 최애가 지도에 추가됐어요! |
| 등록 실패 | 등록을 마치지 못했어요. 적어둔 내용은 그대로예요. 다시 시도해 주세요. |
| 갱신 중단 | 연결이 잠시 끊겼어요. 지금은 마지막으로 확인한 지도를 보여드려요. |

문구의 의미·말투·상태 일치 여부를 검증한다. 예시와 글자가 정확히 같아야 하는 스냅샷 기준으로 사용하지 않는다.

## 현재 문서 상태

- 사용자 스토리 16개, 화면·공통 검증 영역 16개, 흐름도 8개, 화면·품질 분기와 QA 각각 65개를 연결했다.
- 정책 확정 후 QA 상태는 미실행 65개·판정 보류 0개다. 이전에는 미실행44·판정 보류21이었으며 이번 변경은 실행 결과가 아닌 기대 결과 확정이다. 세부 결정 목록은 12개이며 일부 항목에 여러 질문이 포함된다.
- 사용자 흐름과 QA 시나리오를 작성했으며 제품 동작은 아직 구현·검증하지 않았다.
- PRD·확정 정책·스토리·분기·QA를 연결했다. [결정 기록](2-user-story/decisions.md)에 합의 결과와 출시 입력을 구분했다.
- 이 문서 작성은 첫 버전 범위 확정이나 전체 화면·데이터 설계 완료를 의미하지 않는다.
